# Native build variants

Branch: `native-build-readiness`.

Customer identifiers are `com.cleanmate.customer`; cleaner identifiers remain
`com.cleanmate.cleaner`. Normal builds preserve each app's existing URL scheme.
Validation builds add `.validation` to the Android/iOS identifiers, use separate
deep-link schemes and display a Validation suffix. They can coexist with normal
apps without sharing the application storage namespace.

The native config plugin disables arbitrary cleartext traffic in normal release
manifests (Android) and App Transport Security (iOS). Validation permits HTTP to
reach the local test host. Android debug tooling has its own development manifest
override; this is not a release transport guarantee for debug APKs.

Validation configuration requires an explicit `EXPO_PUBLIC_API_URL` using
`http://10.0.2.2:15238`, `http://127.0.0.1:15238` or `http://localhost:15238`.
It rejects missing, external and normal development API URLs. Port 15238 belongs
to the workspace's disposable system-test host. Do not run that host concurrently
with Playwright suites. It creates and deletes its own SQL database and uses fake
email, never the application's configured database.

Check the native manifests generated by Expo, both variants and both platforms:

```powershell
npm run check:native-config
```

The checks assert identifiers, deep-link registration, transport flags and automatic
appearance. Reports go to ignored `.expo/native-config-*.json` files. The native
source folders remain generated and ignored.

Run a normal development build with `npm run android`. For a validation device:

```powershell
$env:EXPO_PUBLIC_API_URL = 'http://10.0.2.2:15238'
npm run android:validation
```

The scripts regenerate native configuration before running Expo so switching
variants cannot silently reuse an existing native directory with the wrong ID.
No `--clean` or deletion of native customizations is performed. iOS commands use
the same wrapper and require macOS/Xcode. A bundle export on Windows is not an
IPA build or an iOS-device test. A normal release also needs its actual HTTPS API
URL, signing and external service configuration; these scripts do not deploy it.

The backend workspace provides `scripts/validation/Start-TestEmulator.ps1` for a
new headless AOSP Android 35 x86_64 AVD under ignored test artifacts and
`Stop-TestEmulator.ps1` to stop only the matching recorded test device. It requires
the local Android SDK image and acceleration. Existing AVDs/physical devices are
not used by that script. Logs and generated AVD data remain under
`CleanMate.Tests/obj/native-validation` after shutdown.
